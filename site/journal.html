Журнал прогресса

Подробное описание каждого этапа выполнения проектной практики — что делали, с чем столкнулись и что получилось.

Этап 1. Создание репозитория и организация структуры

Git Неделя 1, день 1–2

Работу начали с создания репозитория на GitHub по шаблону, предоставленному в задании. Сразу настроили структуру папок: docs/ — для документации, reports/ — для отчётов, site/ — для будущего сайта, src/ — для кода бота.

Оформили основной файл README.md: прописали название проекта, цель, список авторов и предварительный план работы. Освоили базовые команды Git — init, add, commit, push — и настроили связь локального репозитория с GitHub.

Этап 2. Изучение возможностей GitHub

Git Неделя 1, день 3–5

Прежде чем переходить к коду, решили как следует разобраться с инструментами GitHub, которые будем использовать на протяжении всей практики. Изучили работу с Issues: как создавать задачи, назначать ответственных и закрывать их по мере выполнения.

Попрактиковались с ветками: создали ветку dev для разработки и настроили правило, по которому код попадает в main только через pull request. Разобрались с разметкой Markdown — именно на нём будет написана вся документация проекта. Дополнительно изучили, как правильно оформлять коммиты и вести понятную историю изменений.

Этап 3. Начало разработки бота: настройка и база данных

Бот Неделя 2, день 1–2

Приступили к основной части проекта — разработке Telegram-бота. Зарегистрировали бота через BotFather, получили токен и добавили его в файл конфигурации config.py. Установили все необходимые зависимости: Aiogram 3, aiosqlite. Оформили requirements.txt.

Главной задачей первых дней стала база данных. В файле db.py реализовали инициализацию SQLite и создание трёх таблиц: tasks (задачи с дедлайном и статусом), notes (заметки пользователя) и schedule (расписание по дням недели). Все операции с БД написали асинхронно, чтобы не блокировать работу бота.

Структура базы данных SQLite

tasks
id, user_id, text, deadline, done
notes
id, user_id, text, created_at
schedule
id, user_id, day, subject, time

Этап 4. Реализация функционала бота

Бот Неделя 2, день 3–5

Когда база данных была готова, перешли к написанию обработчиков команд в main.py. Реализовали команду /start с приветственным сообщением и главным меню через inline-кнопки (файл keyboards.py).

Постепенно добавили все ключевые функции: добавление задачи с дедлайном (/add_task), просмотр списка задач (/tasks), отметка задачи как выполненной, удаление. Аналогично — работа с заметками: создание, список, удаление. Расписание реализовали по дням недели с возможностью добавлять и просматривать пары. В конце добавили команду /stats, которая показывает количество выполненных задач и общую статистику.

Всё тестировалось вживую в Telegram по мере написания каждой команды. Несколько раз ловили ошибки в асинхронных запросах к БД и потратили время на их отладку.

Этап 5. Отладка и оформление кода

Бот Неделя 3, день 1

После того как основной функционал заработал, занялись чисткой и оформлением кода. Разбили логику по модулям: убрали вспомогательные функции в utils.py, привели именование переменных к единому стилю, добавили комментарии к ключевым блокам.

Прогнали сценарии использования ещё раз: проверили, как бот реагирует на некорректный ввод (например, если пользователь отправил пустое сообщение вместо текста задачи). Добавили базовую обработку ошибок через try/except и понятные сообщения для пользователя. После этого финальная версия бота была закоммичена в ветку main.

Этап 6. Разработка сайта проекта

Сайт Неделя 3, день 2–4

Параллельно с финальной отладкой бота начали делать сайт. По заданию это статический многостраничный сайт на HTML и CSS, размещённый в папке site/ репозитория. Определились со структурой: главная, о проекте, участники, журнал, ресурсы.

Сначала набросали общий макет в голове и сразу написали CSS-переменные для цветов, отступов и радиусов — чтобы стиль был единым на всех страницах. Тёмная цветовая схема выбрана намеренно: она соответствует «технической» тематике и хорошо читается. Верстали от хедера к футеру, сначала главную страницу, затем по очереди остальные.

Адаптивность (mobile-first) добавили через медиазапрос на 850px: колонки перестраиваются в одну, кнопки и заголовки уменьшаются. Проверили вёрстку в мобильном режиме браузера.

Этап 7. Документация и финальное оформление

Документация Неделя 3, день 5

Последним этапом стало оформление документации. Бородина Екатерина подготовила все необходимые Markdown-файлы в папке docs/: инструкцию по установке и запуску бота, описание структуры репозитория, а также журнал прогресса в текстовом виде.

Итоговый отчёт по практике был оформлен в формате DOCX и сконвертирован в PDF. Все материалы добавлены в репозиторий в папку reports/. После финальной проверки все изменения были запушены в main, и репозиторий был подготовлен к сдаче.
